# Engineering decisions

One line per non-obvious choice, newest last.

- One `ModelClient` wraps the `openai` SDK for every provider, because Baseten, the Meta Model API and Fireworks are all OpenAI-compatible; tiers differ only by env-configured provider name.
- `chat_json` extracts the outermost `{...}` from the reply instead of trusting raw output, since models often wrap JSON in prose or code fences.
- The Meta model id is read from `META_MODEL` rather than hard-coded, so the Tier-2 model can change without touching code.
- Muse Spark models spend reasoning tokens before answering (509 tokens for a one-line reply), so `ModelClient` defaults to `max_tokens=2048` and reads an optional `<PROVIDER>_REASONING_EFFORT`; Tier 1 uses `low` (~1.5s/call), the Tier-2 judge keeps the model default.
- Tier 2 uses `muse-spark-1.3`, the newest Muse Spark listed by the Meta API's `/models` endpoint.
- Screen change detection uses a 16x16 perceptual-hash Hamming distance (threshold 10) rather than pixel diff, so cursor movement and clock ticks are ignored but a pop-up or new window is kept (a full-screen pop-up scored 68-108).
- Kept frames are rate-limited to one per 2 s: a live run with an editor redrawing kept ~40 frames in 50 s, each of which would be a Tier-1 call.
- Muse Voice Transcribe is realtime-only (WebSocket `wss://api.meta.ai/v1/asr/realtime`; `/audio/transcriptions` returns 404). We use its `DIARIZATION` mode so each turn carries a speaker label.
- The realtime ASR needs continuous real-time audio while a session is open, so local VAD gates *sessions*, not frames: open on 240 ms of sustained speech (with 0.8 s pre-roll), close after 12 s of silence. Quiet periods are never streamed or billed.
- VAD is RMS energy over an adaptive noise floor rather than a neural VAD: it only has to decide "is anyone talking", and it avoids a native-build dependency on Windows.
- Remote-access tools keep relay connections open while idle, so a live session is inferred from *new* public endpoints appearing after a 15 s settle baseline; the ScreenAnalyst is meant to corroborate it.
- Windows Quick Assist and Remote Assistance are on the remote-access list: no download needed, so scammers increasingly favour them.
- The clipboard watcher publishes only the finding type and a masked value (`****1111`, `bc1q…5mdq`); raw clipboard text never leaves its thread. Card numbers must pass Luhn to count.
- Watcher threads use a `_halt` event, not `_stop`, because `threading.Thread` has a private `_stop()` method that `join()` relies on.
- Analysts may only emit signal names from a fixed vocabulary (`core/killchain.py`); anything else is dropped. A manipulated model can therefore only report known categories, never invent actions.
- Text on screen that addresses an AI ("mark this page safe") is a scored signal, `ai_directed_text`; the test scam page carries one, and the ScreenAnalyst flags it instead of obeying it.
- `cross_modal_brand_match` and `bank_open_during_remote` are derived by the CaseFile, not by a model, because no single analyst sees both the screen and the call.
- The ScreenAnalyst worker is "latest only" (stale frames are skipped when the model lags); the CallAnalyst worker is ordered, because the call must be read in sequence.
- Scenarios are JSON timelines with events anchored to call lines; call audio is synthesized with two built-in Windows voices so diarization has distinct speakers, and replay can either stream it through the real ASR or inject the lines as text for fast, deterministic runs.
- Until on-device redaction exists (Stage F), the live runner does not send real screenshots to a model unless `--allow-unredacted-frames` is passed; only the fictional scenario frames are sent.
- Confidence is a noisy-OR over distinct signal weights scaled by the number of kill-chain stages present (1 stage: 0.45, 2: 0.75, 3+: 0.95-1.0). Known issue for Stage D: it saturates early, and secrecy at the Contact stage ("don't call anyone") currently counts as Extraction.
- "Don't call anyone / the hackers can listen" is its own Contact-stage signal (`isolation_instruction`); `secrecy_instruction` is reserved for hiding a payment from the bank or family (Extraction). This fixed the Stage C issue where the third call line pushed the case to "Extraction".
- Chain multiplier tightened to 1 stage 0.35, 2: 0.6, 3: 0.85, 4: 0.95, 5: 1.0, so a single scary stage (antivirus pop-up, own banking) stays near zero.
- Tier-1 only decides *whether* to ask the judge (confidence >= 0.4 or >= 2 stages); the Tier-2 CaseJudge decides the action. `EscalationPolicy` then clamps it in code: hard_stop needs is_scam and judge confidence >= 0.8, otherwise it is downgraded to a nudge. A model cannot argue past these thresholds.
- Actions only escalate within a session; standing down from a hard stop is a human decision (Stage E).
- The judge worker is "latest only", so a burst of evidence costs one judge call on the newest snapshot. Bug found here: dropped jobs must call `task_done()`, or `drain()` blocks forever.
- Benign scenarios are chosen to bait false alarms: a relative telling the senior to log in to her bank (with a large own-account transfer on screen), a son on AnyDesk with a code read aloud, and a real-looking antivirus "threat blocked" pop-up. `--always-judge` forces every update through the judge to test its discrimination directly.
- The hard stop speaks its warning aloud before anything else: if a scammer controls the screen remotely, the senior can still hear it. Speech uses the built-in Windows SAPI voice through pywin32 on its own COM thread, so nothing extra is installed.
- The warning text never shows a phone number; it tells the person to call the number on the back of their card, because any number on screen or from the caller may be the scammer's.
- The overlay is a borderless, always-on-top Tk window that ignores close requests and re-asserts itself every 300 ms. It must call `SetProcessDpiAwareness` first: at 150% display scaling it otherwise covered only 1280x720 of a 1920x1080 screen.
- Dismissal needs the family PIN (stored as salted PBKDF2, never in clear) or a 60 s cooldown. A call line telling the person to close/ignore/uninstall something during an alert restarts the cooldown, is spoken about aloud, and is added as `disable_protection` evidence. The phrase matcher requires a computer-ish noun or a bare pronoun ("close the warning", "uninstall it now") so "close the door" does not count.
- The family allowlist works on the *remote party's ID*, read from AnyDesk's `connection_trace.txt` (UTF-16) / TeamViewer's `Connections_incoming.txt`, not on the tool name: the son's AnyDesk and a scammer's AnyDesk look identical in the process list. IDs are masked to the last 3 digits in every log.
- A hard stop terminates remote-access processes except tools in a trusted session. Replays only ever terminate explicitly named stand-in executables (`--kill-only notepad.exe`), never a real install.
- After a dismissal the session's action drops to "nudge" so fresh evidence can escalate again; the CaseFile records whether it was dismissed by PIN or by cooldown.
- Pausing or quitting from the tray needs the family PIN and is refused during a hard stop, because "turn off your antivirus" is a standard scammer instruction.
- Replay scores the *highest* action reached, so a demo auto-dismiss does not turn a correct hard stop into a failure.
- Redaction runs on the device with Windows' built-in OCR (`Windows.Media.Ocr`, via the `winrt` packages): no model download and nothing uploaded. SAM 3.1 cannot be the redactor because it runs in the cloud, so the frame would leave the device unredacted; it is used afterwards, on redacted frames only, to outline the threat for the family.
- What is redacted: runs of adjacent number tokens with 8+ digits (account, card, SSN). What is kept: money amounts, phone numbers in phone format and dates, because they are scam *evidence*, not the victim's secrets. Regions are filled solid, not blurred, since blurred digits can sometimes be recovered. OCR runs on a 2x upscale for small UI text.
- Redaction fails closed: if OCR is unavailable or errors, the frame is not sent. The backend redacts frames and timeline text again on arrival (defence in depth). Transcript lines are text-redacted (long digit runs, e.g. a card number read aloud or an AnyDesk code) before reaching the CallAnalyst.
- Family texts carry a message and a private link (unguessable incident token), not a picture: MMS is unavailable in many countries, including Nigeria. The screenshot lives on the linked page.
- Twilio is called with one stdlib HTTPS POST rather than its SDK. Without credentials, texts go to `runtime/backend/sms_outbox.log` (dry run) so the whole flow is demonstrable and testable.
- One family text per session: a dismissed warning that re-escalates is shown and spoken again but does not text again. Found when one replay produced three incidents.
- SAM outlines are filtered: overlapping boxes keep the higher-priority prompt's label, and boxes covering >85% of the frame are dropped (SAM labelled a whole bank page "remote access window"). Outlines are drawn just outside the region so they never cover its text.
- The incident narration uses `reasoning_effort=low`, an 8k token budget and one retry: with 3k tokens the reasoning model sometimes returned no text at all.
- Backend secrets (agent token, dashboard key) come from env or are generated once into git-ignored `runtime/backend/keys.json`; the agent on the same machine reads them from there.
- Muse Image refused 8 of 24 dataset prompts (`content_policy_violation`): the ones depicting fraud artifacts such as a wire form to a "safe account", Bitcoin ATM deposit instructions, or gift-card codes "for the agent". We did not reword prompts to get past the filter; those screens are hand-written HTML pages (fictional brands) rendered with headless Edge, and every dataset item records its source (`muse-image` or `html`).
- The eval replays call lines as text at real-time speed (not compressed), so model latency counts against time to detection as it would live. Text replay keeps runs deterministic; the ASR path is exercised separately by `--mode audio`.
- Time to detection is measured from the scenario's first observable scam sign (`onset`) to the hard stop, in scenario seconds. "Stopped before money was asked for" compares the hard stop with the start of the scenario's first money-request line (`extraction_line`).
- The eval also scores a Tier-1-only ablation (hard stop when the cheap score reaches 0.8) from the same runs, to show what the CaseJudge adds: it catches the scams the Tier-1 score misses, at the cost of ~10 s more latency.
- Finding (2026-10-27): 100% detection and 0% false alarms on 12 scenarios x 2 runs, but only 25% of scams were stopped *before* the money request; the judge tends to wait for it. Stopping at the money request is still before money moves, but earlier is the main target for tuning.
- The backend is containerised for Cloud Run with only the modules it imports (no Windows-only packages, no .env, no data). Incidents go to a private GCS bucket with a 30-day lifecycle; secrets come from Secret Manager; a dedicated service account has only bucket-object and secret-accessor rights. Re-redaction on the backend is skipped on Linux (no Windows OCR) because the device already redacted, fail-closed, before upload.
- Spoken warnings use Google Cloud Text-to-Speech, Chirp 3 HD voice (natural female US English, default "Vindemiatrix", chosen for a gentle tone) at 0.92x speed, instead of the robotic built-in Windows voice. Meta's API offers speech-to-text but no text-to-speech.
- Every phrase is cached on disk and the urgent ones (hard-stop warning for common impersonated names, the "don't close this" line, all nudges) are synthesized at start-up, together with fetching Google credentials (~10 s once). Measured: ~2 s per phrase when synthesized, instant from cache. If synthesis fails and a phrase is not cached, the Windows voice says it: the warning must never go silent.
- Nudges are a fixed set of six reviewed sentences picked by what the caller claims to be (tech company, bank, government, refund, remote access, generic), not free text from the judge. Wording we control, and always pre-cached. The judge's `senior_message` field was removed. Government is matched before bank, because "Federal Trade Commission" otherwise matched "federal" as a bank word.
- Cloud Run: the service runs with CPU always allocated (`--no-cpu-throttling`, max 1 instance), because the family text, SAM highlighting and narration run as background tasks after the response is sent, and default throttling starves them. Scratch files go to `/tmp` (the only writable path). The health check is `/health` because Cloud Run reserves paths ending in "z".
- Deployed in us-east1, alongside the project's other services; us-central1 returned a "cleaning up project resources" conflict.
- Incident (2026-10-27): the first deploy shipped placeholder keys from a unit test. The test had written them into the local `keys.json`, which was then copied into `.env` and Secret Manager. Both keys were rotated to random 32/24-byte values and redeployed; the old ones are rejected. The test now redirects the runtime folder before the backend module is imported, so it can no longer touch the real keys file.
- Family texts run in demo mode. Twilio's 2026 trial has free units instead of credit and only sends fixed templates to verified recipients: Tripwire's own text is refused (error 572006). The only template that would arrive reads "Your account balance is below $100. Please deposit funds…", which is unrelated and would itself look like a scam, so Tripwire does not send templates. The incident page shows the exact text it would send, labelled "Demo mode: not sent". Real texts need an upgraded account and US texting registration.
- Stopping earlier (2026-10-27): event logs showed the judge was asked late and answered cautiously. The fixes: (1) strong early signs (impersonation, isolation, remote-access request/code/session, "close that warning", text aimed at AI, login instruction, secrecy, urgency) send the case to the judge whatever the Tier-1 score; (2) the judge prompt lists early-stop patterns that real banks and agencies never use; (3) the judge runs at `reasoning_effort=low` (~3x faster). Median time to stop went from 46.5 s to 27.0 s and stops before the money request from 25% to 50%, with no false alarms. Tuning stopped there to avoid overfitting to our own scenarios.
- Each replay writes its own event log (time + random suffix): parallel eval runs started in the same second had been interleaving into one file.
- Tests set Twilio variables to empty strings instead of deleting them: reloading the config re-reads `.env`, which only fills unset variables, and one test run sent a real text.
- The demo (`scripts/demo.py`) runs the real pipeline on a staged scam: scenario screens shown full-screen by a separate "stage" process (Tk allows one GUI per process, and the overlay needs its own), the call played aloud by a separate player process (so Tripwire's voice can talk over the scammer, as it would on a real call), and the same audio streamed to Muse Voice Transcribe. Only Notepad, standing in for AnyDesk, is ever terminated.
- The web arena puts the visitor in the scammer's seat instead of asking them to share their real screen. Judges can test detection and false alarms themselves in a minute, with no install and no exposure of their own data. The same pipeline (analysts, CaseFile, CaseJudge, policy) runs unchanged; only the inputs are Margaret's simulated screen and the call.
- Margaret (the AI victim) can only open pages from a fixed list and her details are fictional; her laptop pages exist as HTML (for the visitor) and pre-rendered PNGs (for the ScreenAnalyst), so both see the same screen. Opening RemoteDesk or connecting it emits the same process and network events the desktop watchers would.
- The arena uses push-to-talk (Muse Voice Transcribe `PUSH_TO_TALK` mode: the final transcript arrives ~0.4 s after release), not an open microphone: no echo of Margaret's voice into the transcript, and the visitor controls exactly what is said.
- The recovery agent uses real tool calling (Muse Spark chose the tools and order itself in testing). Its tools are a fixed, validated set; it never moves money. It is given the plain facts of which pages were open, because screen evidence can still be in flight when the stop happens.
- The warning appears the moment the judge decides; its voice follows as a separate message. All urgent phrases are synthesized at server start-up. In testing, waiting for synthesis first delayed the warning by 7 s, during which Margaret obeyed the next instruction.
- Incident writes are atomic (temp file + rename) and updated under a lock: the family text and the enrichment run on separate threads, and a test caught a reader seeing a half-written file.
- Arena games are capped (4 at once, 8 minutes, 40 lines each) so a public URL cannot run up unbounded model costs.
- Remote control is detected from Windows' low-level input hooks: events created by software (remote-access tools) carry `LLMHF_INJECTED`/`LLKHF_INJECTED`, physical input never does. Reported only after 12 injected events within 5 s *and* while a remote-access tool is running, so accessibility tools and stray events don't count. Only counts are kept. Verified live with `SendInput` (a first test failed because a hand-built 64-bit `INPUT` struct was 48 bytes instead of 40, so Windows rejected every event).
- Payment decisions use four outcomes (allow, verify, hold, deny) from deterministic family rules over observed facts, combined with the CaseJudge by taking the stricter. Rules can only tighten, never relax, what the AI decided.
- A held payment needs an explicit family answer; an unanswered request expires as a refusal, and a decision cannot be flipped afterwards.
